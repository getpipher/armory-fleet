# SPEC-5b-3 Implementation Plan — Conversation viewer (full-message overlay)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second overlay level over the 5b-1 Runs-tab timeline: pressing `enter` on a timeline row opens a scrollable **full-message view** of that one event (assistant text in full; tool args/result as journazed); `esc` returns to the timeline with the cursor restored. Pure read-side overlay over `RunLog.replay` — no new seam, store, timer, or journal change.

**Architecture:** One new pure-renderer module (`conversation-rows.ts`: `wrapToLines` + body/header fns) + surgical edits to `fleet-panel.ts`: two new overlay-state fields (`selectedEventIndex`, `fullMessageEvent`) + two stored `SelectList` refs (`timelineList`, `messageBodyList`) so `handleInput` can forward keys to the active overlay. The timeline `SelectList`'s `onSelect` opens the overlay; the body `SelectList`'s `onCancel` closes it. No changes to `RunLog`, `spawnSubagent`, `RunRegistry`, the live widget, or any store.

**Tech Stack:** TypeScript (raw `.ts` via tsx at runtime, no build), `@earendil-works/pi-coding-agent` (`Theme`), `@earendil-works/pi-tui` (`SelectList`, `Text`, `matchesKey`), `node:test` + `node:assert/strict`.

## Plan-level refinements (spec → plan)

1. **5b-3 makes the 5b-1 timeline interactive (strict improvement to v0.6.0).** The v0.6.0 `selectedRun` keypress handler swallows all non-escape keys (`if (matchesKey(data, "escape")) {...}; return;`) — so the timeline `SelectList`, though rendered as a child, never receives input. It is display-only in v0.6.0: not scrollable, `enter` a no-op. 5b-3 *requires* the timeline to be navigable (you must select a row to press `enter`), so this plan forwards input to the timeline `SelectList` via a stored `timelineList` field. `SelectList.handleInput` fires `onSelect` on `tui.select.confirm` (enter) and `onCancel` on `tui.select.cancel` (escape) — so the timeline becomes scrollable (arrows) + `enter`-active, and escape still returns to the Runs list (via the timeline's existing `onCancel`). The term smoke (Task 3) verifies both the new navigability and the overlay.

2. **Input routing via stored SelectList fields + SelectList callbacks (not panel-level escape catch).** Because `Container`/`TUI` routes input only to the focused component (the panel), child `SelectList`s receive keys only if the panel forwards them. This plan stores the active overlay `SelectList` as a field (`timelineList` / `messageBodyList`) during render, and the `handleInput` branch for that overlay forwards all keys to it (`this.timelineList?.handleInput(data); this.invalidate();`). The `SelectList`'s own `onSelect` (enter) + `onCancel` (escape) callbacks do the actions — cleaner than the panel re-catching escape. The panel-level escape catch in the v0.6.0 `selectedRun` branch is removed (the timeline `onCancel` already does the same thing, now actually reachable).

3. **Selection restore on esc-back is one-shot via `setSelectedIndex`.** The 5b-1 render cascade re-creates the timeline `SelectList` on every `renderShell()`. So when `esc` returns from the full-message overlay to the timeline, the timeline is a fresh `SelectList` with `selectedIndex=0`. To put the cursor back on the row the user was viewing, the render branch calls `this.timelineList.setSelectedIndex(this.selectedEventIndex)` (if non-null) right after constructing it, then clears `selectedEventIndex` (one-shot — it's only a restore token; `fullMessageEvent` is the active-view state). `setSelectedIndex` clamps out-of-range indices internally (verified `select-list.d.ts`), so a stale index is safe.

4. **`width` for `wrapToLines` comes from the render branch's available column count.** The body `SelectList` renders at the terminal width pi gives the panel. `SelectList`'s `render(width)` receives the width; but `wrapToLines` runs at construction time (rows are pre-baked into `SelectItem.label`). So the render branch computes `width` from the same source the panel's other lists use. If the exact live width isn't reachable from the render branch, fall back to `80` (documented in a comment) — the `SelectList` still scrolls, and a re-render on resize re-wraps. Resolved concretely in Task 2 Step 3.

```ts
// src/panel/conversation-rows.ts
// SPEC-5b-3 — pure renderers for the full-message overlay (second level over the 5b-1 timeline).
// Plain strings, no theme (codebase convention: theming is applied at the SelectList callback layer).
//
// Journal fidelity (Q2=C): MessageEvent.text is already the FULL assistant text (5b-1 Q1). Tool
// args/result are the journaled excerpt (5b-1: args≤200ch, result≤500ch, errors in-full). The
// toolHeader notes "args/result excerpted" so the asymmetry is honest.
import type { MessageEvent, ToolEvent } from "../runtime/run-log.ts";

/** Word-wrap `text` to `width` columns. Long tokens (no break opportunity) hard-split at `width`.
 *  Explicit `\n` is preserved as a row break (multi-line tool results). Empty → [""]; width≤0 → [""].
 *  Uses Array.from to count by code point (CJK chars are 1 col each in most terminals). */
export function wrapToLines(text: string, width: number): string[] {
  if (width <= 0) return [""];
  if (text.length === 0) return [""];
  const out: string[] = [];
  for (const para of text.split("\n")) {
    if (para.length === 0) { out.push(""); continue; }
    const words = para.split(" ");
    let line = "";
    for (const w of words) {
      if (w.length === 0) continue; // collapse runs of spaces
      if (line.length === 0) {
        // long token with no break opportunity: hard-split at width
        let rest = w;
        while (rest.length > width) {
          out.push(rest.slice(0, width));
          rest = rest.slice(width);
        }
        line = rest;
      } else if (line.length + 1 + w.length <= width) {
        line += " " + w;
      } else {
        out.push(line);
        let rest = w;
        while (rest.length > width) {
          out.push(rest.slice(0, width));
          rest = rest.slice(width);
        }
        line = rest;
      }
    }
    out.push(line);
  }
  return out;
}

/** Body for an assistant message: the full text, wrapped. */
export function messageBody(e: MessageEvent, width: number): string[] {
  return wrapToLines(e.text, width);
}

/** Body for a tool event: `args:` + indented args, `result:` + indented result. */
export function toolBody(e: ToolEvent, width: number): string[] {
  const inner = Math.max(2, width - 2);
  const lines: string[] = ["args:"];
  for (const l of wrapToLines(e.args, inner)) lines.push("  " + l);
  lines.push("result:");
  for (const l of wrapToLines(e.result, inner)) lines.push("  " + l);
  return lines;
}

/** Header for an assistant message event. Omits the token segment when usage.total is absent. */
export function messageHeader(e: MessageEvent): string {
  const turn = Math.max(0, e.turnIndex);
  const tok = e.usage?.total != null ? ` · ${e.usage.total} tok` : "";
  return `── assistant · turn ${turn}${tok} ──`;
}

/** Header for a tool event. Notes "args/result excerpted" (Q2=C honest asymmetry). */
export function toolHeader(e: ToolEvent): string {
  const turn = Math.max(0, e.turnIndex);
  const glyph = e.isError ? "✗" : "✓";
  return `── tool: ${e.toolName} · turn ${turn} · ${glyph} · args/result excerpted ──`;
}
```
